## 二、保留（经核对不属于缺陷）

- **`/categories` 精确比对前 3 个 chip 的顺序**（Spec）：期望值与 SSR 都来自同一个 `/api/v1/tags`（`ORDER BY t.name`），渲染器按输入顺序 `slice(0, 3)` 已由 `taxonomy-groups.test.ts` 钉住；改成集合比对会漏掉「取错前 3 个」的回归。
- **`tag_count` 缺字段恒为 0，压过 `catTags.length` 兜底**（Spec）：#119 改动清单明确要求「缺字段降级为 0」；Worker 契约保证该字段存在（非目标禁止改 SQL / 响应），故不保留第二条兜底真值。若未来 Worker 部署滞后于前端，仍会显示 0，属该口径的已知代价。
- **`/tags` 断言 SSR 标签总数等于接口标签数**（Spec）：两端请求同一端点；响应若改成分页，SSR 与真值同步只看到同一页，断言仍成立。
- **`TaxonomyItem` 的按 kind 可选字段与 `id?: number`**（Standards / Spec）：#119 明确要求「可选字段」；`id` 为修「前 3 个 chip 恢复」所必需（`renderCategoryCards` 按 `cat.id` 分桶）。页面侧 `as any[]` 是 #97 起的既有桥接，不在本票范围。
- **`docs/agents/testing.md` 不在改动清单内**（Spec）：仓库惯例是测试矩阵随回归脚本同步，且该段本身需要修正（见已修 #1）。
- **禁用 JS 的 SSR context 不自行取接口真值**（Spec）：真值先由正常页面取，再喂给无 JS 页面做 SSR 断言；无 JS context 无法 fetch，这是 #117 起的分工。
