## Spec

### (a) 缺失 / 部分实现

1. **布局断言没覆盖规格点名的内容。**
   规格：「`.milkdown-host .ProseMirror` 的列表项有列表样式与缩进」。新 `scenarioLayoutStyles` 断言的是 `display:flex`、`gap:10px`、标签槽 `32px`，不是 `list-style` / 缩进。部分实现。
2. **没有响应式 / 主题验证证据。**
   规格：「跑 `scripts/verify-editor-responsive.mjs`（工具栏换行 / 280px / 375px）与 `scripts/verify-visual-friendliness.mjs` 的编辑器目标，亮暗主题各一遍」。两个脚本都没动，ADR 与复审记录也没写运行结果。新场景只跑一个默认视口，也没有断言主题颜色。
3. **链接浮层 / 表格未断言。** 规格验收：「链接浮层、表格边框均正常」。只钉了 toolbar / slash menu / list；ADR 只声称选择器存在于产物中。
4. **主题加载顺序是推理，不是实测。** 规格：「需要实测确认 common CSS 的加载顺序不会把主题顶回去」。ADR 用优先级推理（「`:root .milkdown` 映射（优先级高于 `.milkdown`）」）代替实测。

### (b) 范围蔓延

- `docs/ARTICLE_EDITOR_UPGRADE.md`（主题 / 布局段落）与 `docs/agents/testing.md`（「12 个 → 13 个 `withScenario` 场景」）被改，而规格的文档清单只点名 ADR 0006 与复审文件。
- `docs/reviews/2026-11-18-article-editor-module.md` 整体新增（141 行）。规格说的是「追加一行『布局缺失已修复（本票）；P1-1 / P1-2 仍待处理』」；那行确实在，但整份模块审查随本 PR 落地，而不是只追加一行。

### (c) 看起来实现了、实际不对

- **reset CSS 把 120px 编辑器内边距带回来。** 规格验收：「280px / 375px / 桌面三档无横向滚动，工具栏不溢出」。`common/style.css` → `reset.css` 带 `.milkdown .ProseMirror { padding: 60px 120px; }`。唯一的覆盖 `src/admin/admin-shared.css:1742` `.milkdown-host .ProseMirror` 优先级相同且不含 `padding`，而懒加载后插入的 `createEditor.*.css` 靠源码顺序胜出 —— 于是 280 / 375px 下正文两侧各被 120px 挤掉，还被 `.milkdown-host { overflow-x: hidden }` 掩盖。新场景与（未运行的）响应式脚本都没有断言这一点。
- **`crepe-theme.css` 的理由有误导性**：「顺序保持 common → classic：布局先落地，主题变量后覆盖」—— `classic.css` 只定义变量，真正的主题来自 `admin-shared.css`，所述顺序保证并不是主题生效的原因。

构建产物与规格一致（`dist/_assets/createEditor.fl6yckB1.css` 含 `.milkdown-toolbar` / `.milkdown-slash-menu` / `.milkdown-block-handle` / `.milkdown-list-item-block`）。

## 结论
