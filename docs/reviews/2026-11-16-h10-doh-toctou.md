## 实现摘要

`worker/src/handlers/img_proxy.ts` 共用的拉取入口 `fetchWithValidatedRedirects`（img / text / scrape 三通道）作短期收紧：

1. **判定带元信息**：`resolveAndCheckTarget` 从返回 `"ok" | "blocked" | "failed"` 改为返回 `ResolutionDecision { status, reason, blockedIps, checkedAt }`。reason 区分 `literal` / `doh` / `lookup_failed` / `empty` / `redirect_validation` / `malformed_location`。
2. **TTL 缩窗**：新增 `RESOLUTION_TTL_MS = 1_000`。同一请求内按主机复用解析判定（同主机 http→https 不重复 DoH），但每次 `fetch` 前检查 `Date.now() - checkedAt`，超过 1 秒即重新 DoH 后再建连。窗口上界从「整个请求生命周期（总超时 10 秒）」压到 1 秒；**不宣称消除 TOCTOU**。
3. **结构化告警**：所有 `blocked` 出口统一 `logSsrfBlocked()`，输出 `[ssrf-blocked] { event, channel, host, hop, reason, blocked_ips, at, client_ip_hash? }` JSON 到 `console.warn`；client IP 只记 SHA-1 哈希，不记原始 IP 或完整目标 URL（避免 query 中的 token 入日志）。img 通道调用时传 `{ channel: "img", clientIp: ip }`，其他共用通道留 `channel: "unknown"` 但同样有日志。
4. **残留三层防护不动**：URL 同步校验、重定向逐跳复核、流式大小限制与总超时原样保留；DoH fail-closed 语义（查询失败/超时/无记录一律拒绝）不变。

测试：`worker/tests/img_proxy.test.ts` 新增 3 条 H10 测试（TTL 过期后重新 DoH 并拦截 rebind 到 metadata 的第二跳、DoH blocked 的结构化日志字段与脱敏、重定向同步校验 blocked 也有日志）；原有 20 条 SSRF/解析测试全部保留通过。该测试文件被 pre-commit prettier 从单引号整体重排为双引号（格式噪音，不计 finding，与 #84 `comment.ts` 同类）。

## Standards 轴

1. **[judgement] TTL 取 1000ms**：同主机重定向通常在毫秒级完成，1 秒兼顾「不重复 DoH」与「缩窗」；DoH 单次超时 3 秒不计入窗口（checkedAt 在查询完成时取）。值为保守工程选择，未做生产压测定标。**可接受**。
2. **[judgement] 日志走 console.warn 而非新告警通道**：仓库现有结构化日志惯例即 `console.error/warn` + 前缀文本（见 `auth_handler.ts` / `router.ts`），Cloudflare 日志可直接按 `[ssrf-blocked]` 建告警规则；未引入外部告警服务（超出范围）。**可接受**。
3. **[judgement] client IP 哈希而非原文**：`client_ip_hash` 用已有 `sha1Hex` 派生，够关联同一攻击源，又不把原始 IP 写进日志。**可接受**。
4. **[judgement] 共用入口改动影响 text/scrape**：它们同样获得缩窗与日志收益，但本票不扩展其业务语义；日志 channel 标 `unknown` 如实反映缺少上下文。**可接受**。

**Standards 总结：0 hard / 4 judgement（均可接受），无阻断项。**

## 取舍与残余风险

- **TOCTOU 未根治**：1 秒 TTL 只压缩窗口；短 TTL 双答案 DNS 仍可能在 DoH 与 Workers 内部解析间给出不同答案，实际连到内网 / `169.254.169.254`。Workers `fetch` 无法绑定已校验 IP。根治方案（Durable Object 或自建 connect 层、IP 直连 + Host/SNI/证书校验）**不纳入本票**，已移交 #109（ready-for-human，需网络层设计）。
- **日志是告警输入而非告警本身**：需运维在 Cloudflare 日志规则中配置 `[ssrf-blocked]` 告警；本票未配规则（无 zone 写权限，且属运维面）。
- **其他共用通道上下文缺失**：text_proxy / scrape 经同一入口也会缩窗与记录日志，但 `channel:"unknown"`，无法从日志区分通道；如需细分可在后续票传 context。
- **生产验证未做**：本地以 fetch stub + fake timers 验证语义，未在生产用真实双答案 DNS 探针验证 1 秒窗口的实际效果。
- **格式噪音**：`img_proxy.test.ts` 被 prettier 从单引号整体重排，diff 行数偏大但无逻辑变化。
