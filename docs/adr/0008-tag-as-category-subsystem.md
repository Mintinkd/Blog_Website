# 标签系统改为分类子系统：`tags.category_id` 1:N 归属模型

2026-11-17。本站原有标签与分类是两个平行体系：文章归属一个分类（`articles.category_id`），同时挂任意多对多的标签（`article_tags`），标签之间、标签与分类之间没有任何结构关系。后果是前台与后台只能「平铺」展示标签，无法回答「这个分类下有哪些标签」「这个标签属于哪个板块」的问题，分类页 / 标签页 / 搜索页之间也缺乏互相导流的锚点（#75 的动机）。本 ADR 锁定「标签归属分类」的领域模型与契约，避免 schema / API / UI 各自解释。实施票为 #76（契约）→ #77（迁移）→ #78（读 API）→ #79（写 API）→ #80（后台）→ #81（前台）→ #82（数据整理收尾）。

## 决策

五个已锁定决策（#75 母票裁定，本文记录后果与边界）：

### 1. 标签 → 分类是 1:N：每个标签只属于一个分类（`tags.category_id`）

`tags` 新增可空列 `category_id INTEGER REFERENCES categories(id)` + 二级索引（`schema-tag-category-incremental.sql`）。**迁移期允许 NULL**（回填完成前不破坏现有数据）；回填完成、应用层写入路径全部补齐归属后，由应用层保证必填——首批**不做 DB 级 `NOT NULL`**（SQLite 加 `NOT NULL` 需重建表，风险与收益不成比例；列语义由 worker 写路径 + 测试钉住）。分类被删除时标签不能悬空：`DELETE /categories/:id` 在分类名下仍有标签时返回 400（#79），先把标签移走或批量移到未分类。

后果：查「某分类的全部标签」是 `WHERE tags.category_id = ?` 的索引扫描；标签不再可能同时出现在两个分类组里，前台分组渲染（#81）无歧义。

### 2. 文章分类权威不变：`articles.category_id` 仍是唯一权威

标签归属是「标签的组织方式」，不是「文章的分类方式」。文章属于哪个分类**只**由 `articles.category_id` 决定，标签不反向决定文章分类；给文章打一个属于其他分类的标签（跨分类标签）是允许的存量现实，前台用 `data-cross-category` 标记展示（#81），不静默改写文章分类。首批对「文章标签必须属于文章分类」只做**软约束**：跑审计、人工整理到 0 冲突（或列出明确例外）后，#82 再决定是否开启硬校验（默认关闭，开启时冲突文章 400 且提示具体标签）。

后果：跨分类场景不需要数据迁移即可上线；硬校验的开启与否是运营决策，不是 schema 决策。

### 3. 命名空间不变：`tags.name` / `slug` 继续全局唯一，URL 结构不变

标签的名字与 slug **不**按分类建立命名空间（不做「同分类内唯一」），存量标签的 name / slug / 引用（`article_tags`、FTS、外链）零改动；前台继续 `/tags`、`/tags/:slug`、`/categories`、`/categories/:slug`，**不做** `/categories/:cat/tags/:tag` 之类的第三级路径，也不加 301。分类在标签语境里只以三种形态出现：分组头、面包屑、筛选参数（`?category_slug=` / `?tag=`）。

后果：FTS external-content 触发器不会被本批触碰（改名不在本批范围，避免触发器刷新问题）；所有既有回归选择器（`#tags-cloud` / `.tag-item` 等）继续有效。

### 4. 存量回填规则：按文章归类投票，平票取小 id，无文章归未分类

对每个存量标签统计「引用它的已发布与草稿文章各自挂在哪个 `articles.category_id`」，取**出现次数最多**的分类回填 `tags.category_id`；出现次数并列时取**较小的分类 id**（确定性，避免迁移脚本两次执行结果不同）；没有任何文章引用的标签归入种子分类「未分类」（`uncategorized`）。回填只写 `tags` 表，**不**删改 `article_tags`、**不**自动改任何文章的 `category_id`。回填后的跨分类残留（文章分类 ≠ 标签归属）由审计 SQL 清单产出，交给后台人工整理（#82）。

后果：规则完全确定、可离线重放（对同一份迁移前导出重复执行结果一致）；「标签被文章用什么分类用得最多」比「创建者当时手滑选了什么」更能反映真实归属。

### 5. 权限沿用既有所有权模型

创建标签：editor 可用（与现状一致），可选携带 `category_id`；缺省归「未分类」。修改标签归属：**标签创建者**或**目标分类所有者**可改（`canManageTag`，#79 / #80）；改名 / 改 slug 不在首批范围（见决策 3）。删除标签：仅 admin。删除分类：仅 admin，且有标签时 400。

后果：editor 之间不能把别人的标签移进自己的分类再改名——虽然首批不改名，权限模型仍按「将来会改名」的口径收口，避免后续放宽时翻旧账。

## 回滚原则

**只回代码，不急着回 schema。** `tags.category_id` 是增量可空列，旧代码读不写它都不会报错，所以回滚的正确姿势是把 worker / 前端代码回退到 #76 之前的版本直接部署，列留在库里无害。**事故中禁止 `DROP COLUMN`**（SQLite 重建表 + 生产写流量 = 二次事故）；需要恢复数据时用迁移前的 `wrangler d1 export` 备份导入。新 → 旧方向的备份导入**不保证兼容**（旧代码不认识 `tags.category_id`，导入列会丢失），文档写明、回滚一律使用迁移前备份。FTS 不做 `rebuild`；若未来开放标签改名，走定向刷新而非全量重建。

## Consequences

- **读放大可控**：`GET /tags`、`GET /categories` 从单表查询变成 join categories / 计数子查询，均为毫秒级小表；`?category_slug=` 过滤走新增索引。
- **响应形状是加法的**：`TagBrief` / 搜索结果 / 标签列表新增 `category_id` 与 `category`（迁移期为 `null` 允许），既有字段（`id` / `name` / `slug`）不变，旧前端兼容（#78 验收项）。
- **审计先行**：上线前在「迁移前的生产导出副本」上演练迁移（#77 验收项），行数不变 + `NULL` 归零 + 跨分类清单产出，三关都过才允许在生产执行。
- **未做**（明确记录，防止实现时顺手加）：DB 级 `NOT NULL`、分类内标签命名空间、三级 URL、标签改名、文章分类硬校验（默认关，#82 决策）、`article_tags` 结构变更。
- **测试**：worker 侧 `worker/tests/tag_category_read.test.ts` / `worker/tests/category_tags_read.test.ts` 钉读 API 契约（#78）；回填规则由迁移脚本的审计 SQL 与 D1 副本演练钉住（#77）；前台分组 / 筛选 / 卡片由根包 `tests/taxonomy-groups.test.ts` / `tests/taxonomy-filter.test.ts` / `tests/article-card.test.ts` 钉住（#81）；矩阵见 `docs/agents/testing.md` 的 taxonomy v2 小节。

## 实施修订：前台信息架构收口（#115 / #118 / #117 / #116）

决策 3「URL 结构不变」在 #115 批次被复核：保留 `/tags`、`/tags/:slug` 作为兼容入口，不做删除或 301，但**前台主路径收口到分类筛选页**——标签 chip 不再是独立的第二浏览路径，而是分类的子入口。具体修订（不改领域模型、不改 URL 结构）：

- 导航移除「标签」项（#118），搜索页不再列 taxonomy 区块，仅保留关键词搜索；#121 起再收口：首页移除「热门标签」区块、`/categories` 移除「全部标签」入口，`/tags` 仅保留 `/tags/:slug` 的「标签不存在」空态作为前台回流入口（面包屑指向分类页），路由本身仍返回 200，不做删除或 301。
- `/categories/:slug?tag=:tag` 升级为 SSR 筛选（#117）：服务端解析并校验标签归属，直出筛选结果与 chip（`aria-current="page"`），禁用 JS 时走整页导航。
- 全站标签 chip（文章卡片、文章详情、分类目录预览、标签页同分类标签、`/tags` 目录 chip）统一走单源 `src/utils/tagLinks.ts::tagChipHref`（#116）：有分类 → `/categories/:cat?tag=:tag`，无归属（迁移期）→ `/tags/:slug`。分类 slug 走路径编码、标签 slug 走查询编码，避免 `&` / `=` / 路径穿越字符逃逸。首页「热门标签」区块随 #121 移除，不再是 chip 渲染点。
- 这些修订与决策 3 一致：没有新增三级 URL、没有改标签命名空间、没有触碰 API / D1 契约；只是把已有 URL 的**前台入口权重**从「标签页」移到「分类筛选页」，`/tags` 系列仍返回 200。
