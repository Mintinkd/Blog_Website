# 0001 · 设置白名单：规则描述符单源 + 双端生成物

2026-10-18（issue #27）。设置值校验此前后双份手抄：根包 `src/utils/settings.ts` 读侧 `sanitizeSettings`（按字段回落）与 worker `worker/src/handlers/settings.ts` 写侧 `validateSettings`（拒绝 400），注释自称「双端同一套」却无同步机制。决定：仓库根收敛为一份手写规则描述符（4 条命名 pattern、数值范围、copy 长度上限、各分区字段清单），生成脚本为根包与 worker 各生成一份同构 TS 模块，两侧实现重写为消费生成物的通用逻辑（逐字段应用不再手写）；生成物提交进库，CI 以「重新生成 → 与提交版 diff 必须为空」的漂移断言守护。跨包合法化契约、生成物结构、部署面都受影响，返工成本高，故立档。

## Considered Options

- **CI 同步测试**（#27 候选 b）：以同一夹具分别执行两端净化器，断言输出一致。只守恒不收敛——仍是两处手工编辑点，漂移修复成本不减，弃。
- **读侧运行时取 API**（#27 候选 c）：写侧为唯一事实源，前端不本地持规则。前端合法性绑上运行时网络路径，部署面反而变大，弃。

## Consequences

- 语义不变：现有正则、范围、上限逐字保留，只换来源。
- 已知残留：两份手抄 `getDefaultSettings`（字段键集）不在本决策收敛范围；两侧改为遍历生成物中的字段清单后，键集漂移由生成物约束兜底，而非各自的 defaults。
